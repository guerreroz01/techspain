# Lote de publicación — 19/10/2026

## Objetivo

Publicar las 14 piezas seleccionadas del informe diario del 19/10 (`npm run news`: 949 novedades, 370 en verticales), cada una con su compañero EN, una sola promoción `featured`, índice regenerado, build verde y commit de lote.

## Por qué así

- El usuario pidió publicar **todo** lo disponible (las 14 de la lista presentada: 7 fuertes + 4 nicho + 3 tutoriales) y exigió **un subagente a la vez** (secuencial, sin paralelo). Eso manda sobre el «todos en paralelo» del playbook.
- La política de entrega del repo es **un commit de lote sobre `main`** (histórico: «20 artículos 14/10/2026», etc.). No hay flujo de PRs: no aplica cadena ni `size:exception`.
- RDD está **off** (decidido global): sin consentimiento ni review ceremony; solo build + sitemaps.
- TDD: no aplica (contenido editorial; la verificación funcional es `npm run build` + `npm run test:sitemaps`).
- Slug/tema ya verificados en sesión: 14/14 `libre`, duplicados descartados con `npm run find`.

## Restricciones (no negociables)

- Un escritor (`general`) a la vez; cada uno escribe **solo** `src/content/news/<vertical>/<slug>/` (ES).
- Sin `author` en frontmatter; `featured`/`breaking` en `false` (promoción al final, exactamente una).
- `pubDate: 2026-10-19` en las 14.
- Compañero EN por artículo vía `npm run translate:en -- <vertical>/<slug>` (fallback: subagente remoto secuencial, también de a uno).
- **Un solo** `npm run build` al final, después de los EN; luego `npm run index`, promoción, commit.

## Forecast

~1.400–2.100 líneas autoría (14 × ~100–150). Entrega: un commit de lote sobre `main` (convención del repo).
