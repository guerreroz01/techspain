# Lote de publicación — 26/10/2026

## Objetivo

Publicar las 5 piezas seleccionadas en la revisión de fuentes del 26/10, cada una con su compañero EN, una sola promoción `featured`, índice regenerado y build verde.

## Por qué así

- El usuario pidió revisar fuentes y luego «lanza los subagentes y que los redacten todos»: implementación autorizada del lote completo.
- Un subagente `general` por artículo, en paralelo (playbook `skills/redaccion-prensa/DELEGATION.md`). Cada escritor toca una sola carpeta ES, así que no hay solape de archivos.
- Verificación funcional: `npm run build` + `npm run test:sitemaps`. No aplica TDD (contenido editorial).
- Entrega: un commit de lote sobre la rama de trabajo; push y PR quedan como decisión del usuario.

## Restricciones (no negociables)

- Sin `author` en frontmatter; `featured`/`breaking` en `false` (promoción al final, exactamente una).
- `pubDate: 2026-10-26` en las 5.
- Cover ≥ 1200 px de ancho, `npm run covers --strict` y `npm run quality --strict` por pieza.
- Compañero EN por artículo vía `npm run translate:en -- <vertical>/<slug>` (fallback: subagente remoto).
- **Un solo** `npm run build` al final, después de los EN; luego `npm run index` y promoción.

## Forecast

~500–750 líneas de autoría (5 × ~100–150). Muy por debajo del presupuesto de revisión de 400 líneas por PR solo si se cuenta el cuerpo; el lote completo supera ese umbral, así que la entrega va como un commit de lote único según la convención histórica del repo (sin flujo de PRs).
